# Architecture

Executive PA is a private single-user PWA composed of a React/Vite frontend and a layered Node.js/Express backend backed by MongoDB (Prisma). This document reflects the codebase as of Phase 7.

## System overview

```
+-----------------------------+         +----------------------------------+
|  React 18 + Vite SPA (PWA)  |  HTTPS  |  Node.js + Express API           |
|  - MSAL (AC + PKCE)         | ------> |  Route -> Middleware -> Validator|
|  - React Query + Router     |  JSON   |  -> Controller -> Service        |
|  - Service worker shell     |         |  -> Repository -> Prisma         |
+-----------------------------+         +------------------+---------------+
        sessionStorage JWT only                            |
                                                    MongoDB
```

The SPA stores only its own short-lived backend session JWT (sessionStorage) plus a Graph access token for read-only calendar calls. No secrets live in the client bundle or localStorage.

## Backend layering

`server/src` follows one request path, in order:

1. **Route** (`routes/*.routes.js`) — URL → handler wiring only.
2. **Middleware** — `requireAuth` (verified session), `security.js` (Helmet, CORS allowlist, rate limit), `validate.js` (Zod body/params/query whitelist).
3. **Controller** (`controllers/`) — HTTP concerns: extract inputs, call service, shape `{ success, message, data }` responses.
4. **Service** (`services/`) — business rules, orchestration, notification dedupe.
5. **Repository** (`repositories/`) — Prisma queries only.
6. **Prisma** — schema in `server/prisma/schema.prisma` (MongoDB connector; collections mapped via `@@map`, schema shipped with `prisma db push`).

Error flow: services throw typed `AppError`s (`ValidationError` 422, `NotFoundError` 404, `UnauthorizedError` 401, `ForbiddenError` 403); the central `errorHandler` converts them (and `ZodError`s) into safe JSON, hiding internals in production.

## Reliability model (Phase 7)

- **Startup validation:** `config/env.js` fails fast on missing/malformed required variables (stricter in production).
- **Liveness:** `GET /api/health` — process-up signal, no dependencies touched.
- **Readiness:** `GET /api/ready` — pings the database (`$runCommandRaw { ping: 1 }`) through Prisma; 503 when the database is unreachable.
- **Graceful shutdown:** SIGINT/SIGTERM stop the scheduler, close the HTTP server, disconnect Prisma; forced exit after 10 s.
- **Scheduler safety:** in-process 5-minute ticks with `unref()`, never started in `NODE_ENV=test`; notification `dedupeKey` (unique per user+key) makes restarts idempotent — no duplicate alerts.
- **External failure handling:** Graph sync errors are recorded on `CalendarConnection` (status/error fields) and surfaced as degraded state, not crashes.

## Frontend structure

- `pages/` — one component per route; pages compose shared `components/` (forms, layout, common).
- `hooks/` — behaviour (speech, service-worker updates); `services/` — the single axios API layer with token injection.
- `context/` — `AuthContext` (session lifecycle) and `ToastContext` (feedback).
- PWA: `public/manifest.webmanifest`, `public/icons/` (generated by `server/scripts/generate-icons.js`), `public/sw.js` (app-shell only; API/cross-origin requests are network-only), update banner in `AppLayout` via `useServiceWorkerUpdate`.

## Provider replaceability

Hosting, database and notification providers are configuration-driven (`render.yaml`, `netlify.toml`, env vars). No business logic references a specific vendor; if a free tier disappears, swap the provider without code changes.
